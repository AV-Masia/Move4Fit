# Архитектура приложения Move4Fit

Документ описывает приложение с двух сторон: **продуктовую** (экраны, навигация,
пользовательские потоки) и **техническую** (структура кода, модель данных, слои).
Основано на текущем коде `app/` и `src/` и на продуктовой доске
(`docs/структура.excalidraw`, см. [разделы/](разделы/)).

**Стек:** Expo SDK 58, Expo Router (file-based), React Native 0.88, React 19,
TypeScript, хранение — локально через AsyncStorage. Платформы: iOS, Android, Web
(react-native-web).

---

## Часть 1. Продуктовая архитектура

### Роли

- **Родитель** — основной пользователь, заводит профиль ребёнка, проходит анкету,
  проводит занятия, даёт обратную связь.
- **Ребёнок** — отвечает на вопросы о самочувствии/сложности (по возможности
  визуально — «мордочки», иконки).
- **Куратор/специалист** — через вкладку «Куратор» (чат); даёт допуск и смотрит прогресс.
- **Админ** — отдельный раздел `admin/` для контента (упражнения, статьи, занятия,
  цели, семьи).

### Карта экранов

```
Старт
 └─ welcome ─ sign-up ─ rules ─ child/new ─ child/questionnaire ─ child/result
                                                                      │
                                                                      ▼
Основное приложение — таб-бар:
 ├─ (tabs)/index       «Сегодня»  — занятие дня, цель, состояние
 ├─ (tabs)/progress    «Динамика» — тесты и результаты, значки
 ├─ (tabs)/read        «Читать»   — статьи для родителей
 ├─ (tabs)/support     «Куратор»  — чат со специалистом
 └─ (tabs)/profile     «Профиль»  — ребёнок, настройки, повтор анкеты

Модальные / вложенные экраны:
 ├─ workout            — прохождение занятия (видео, выполнение, обратная связь)
 ├─ exercise/[id]      — карточка упражнения (3 уровня сложности, отдельная практика)
 ├─ test/[id]          — тест динамики (секундомер, ввод результата)
 ├─ goal               — выбор/формулировка цели семьи и её оценка
 ├─ article/[id]       — статья
 └─ chat               — переписка с куратором

Админ (admin/):
 ├─ index, settings, goals
 ├─ exercises/ (index, edit)
 ├─ articles/  (index, edit)
 ├─ workouts/  (index, edit)
 └─ families/  (index, [id])
```

### Ключевые пользовательские потоки

**Онбординг и допуск** (шаги 1–3 с доски):
`welcome → sign-up (+ согласие) → rules (принятие правил) → child/new (имя, возраст, пол)`.

**Функциональный тест и подбор** (шаги 4–5):
`child/questionnaire (тест движений + вопросы об ограничениях) → child/result
(функциональный уровень, исключённые риски, нужен ли допуск врача)`.
При «блокирующих» особенностях (ответ «да» на вопрос, требующий разрешения врача, —
`CLEARANCE_FLAGS`: неконтролируемые судороги, недавняя операция, заболевание сердца,
«другие запреты врача») план занятия пуст, пока родитель не подтвердит допуск
(гейт продублирован в `workoutBlock` и в `buildTodayWorkout`). Ответы «не знаю» занятие
не блокируют — они только убирают соответствующие упражнения. Отдельного автоматического
маршрута «при сомнениях → к куратору» пока **нет** (открытый вопрос, см.
[разделы/04-безопасность-mvp-gmfcs.md](разделы/04-безопасность-mvp-gmfcs.md)).

**Тренировка и обратная связь** (шаги 6–7):
`(tabs)/index → workout → по упражнениям (видео на весь экран, таймер) → обратная
связь ребёнка (сложность/усталость/что дальше) и наблюдения родителя → отметка
занятия`. Прогрессия корректирует сложность (2× «легко» → сложнее, «тяжело» → проще).

**Прогресс:** `(tabs)/progress → test/[id]` (тесты динамики), значки за регулярность.

> Пожелания к интерфейсу этих экранов (иконки сложности, «мордочки», цвет без
> гендерной привязки, видео без прокрутки) собраны в
> [разделы/06-ui-аннотации.md](разделы/06-ui-аннотации.md).

## Часть 2. Техническая архитектура

### Слои

```
app/                 ← Expo Router: экраны и навигация (тонкий слой UI)
 └─ зовёт →
src/state/AppState   ← React Context: единое состояние + загрузка/сохранение
 └─ использует →
src/domain/          ← бизнес-логика, чистые функции + типы (ядро, без React и I/O)
 └─ персистится через →
AsyncStorage         ← локальное хранилище на устройстве
```

Правило зависимостей: `app` → `state` → `domain`. Доменный слой не зависит от React
и от Expo — его можно тестировать изолированно (`*.test.ts` рядом с модулями).

### Доменный слой (`src/domain/`)

| Модуль | Ответственность |
|---|---|
| `types.ts` | Все типы данных (см. ниже) |
| `questionnaire.ts` | Вопросы теста движений и вопросы об ограничениях |
| `functionalLevel.ts` | `assess()` — ответы → возможности, функциональный уровень, флаги безопасности |
| `selection.ts` | Подбор упражнений под уровень, возможности, возраст и исключённые риски |
| `exercises.ts`, `library.ts` | Библиотека упражнений и её фильтрация |
| `progression.ts` | Изменение сложности по обратной связи (`applySessionResult`) |
| *(логика безопасности)* | Противопоказания и допуск реализованы в `questionnaire.ts` (`FLAG_EXCLUSIONS`, `CLEARANCE_FLAGS`) и `functionalLevel.ts` (`assess`, `excludedRisks`); отдельного `safety.ts` нет. Проверяется тестами `safety.test.ts` и `safety-golden.test.ts` |
| `profile.ts` | Возраст «растёт» сам (`currentAgeYears`), перерывы, повторный допуск |
| `goals.ts` | Цели семьи и их оценка |
| `achievements.ts` | Значки за регулярность |
| `ratings.ts` | Обратная связь (сложность/усталость) |
| `summary.ts` | Сводка для куратора/врача |
| `content.ts`, `admin.ts` | Контент и админ-логика |
| `storage.ts` | Сериализация/восстановление состояния (`restoreState`) |

### Состояние и персистентность (`src/state/AppState.tsx`)

- Единый React Context поверх `useState` + `useEffect`.
- Всё состояние (`PersistedState`) сериализуется целиком в **один** ключ AsyncStorage
  `move4fit/state/v1` (не по отдельным ключам). Поля:
  - массивы: `sessions`, `trackingResults`, `pastGoals`, `readArticles`, `practices`, `chat`;
  - объекты и значения: `user`, `child`, `assessment`, `progress`, `goal`, `theme`,
    `rulesAcceptedAt`, `painAcknowledgedSessionId`, `breakHandledSessionId`, `profileNotice`.
- Обрабатываются проблемы хранилища: `corrupt` (данные не прочитались — копия
  откладывается в отдельный ключ `move4fit/state/v1/unreadable`) и `unavailable` (не сохраняется).

### Модель данных (ядро `types.ts`)

Цепочка алгоритма (зашита в комментарии к модели):

```
возраст → ограничения/противопоказания → функциональные возможности
(тест из 5 пунктов + GMFCS) → функциональный уровень → подходящие упражнения
→ уровень сложности → прогрессия
```

Основные сущности:
- **`ChildProfile`** — ребёнок (возраст, пол, подтверждение допуска врача). Диагноз
  **не хранится**: подбор идёт по умениям и запретам врача.
- **`FunctionalLevel` (1–5)** — внутренний уровень, близкий к GMFCS; родителю
  показывается словами, не термином.
- **`Capability`** — конкретные умения (держит голову, сидит сам, стоит у опоры,
  ходит сам, бегает и т. д.).
- **`SafetyFlag` / `SafetyAnswer`** — особенности здоровья (судороги, операция, шунт,
  хрупкость костей, нестабильность шеи…) с ответами да/нет/не знаю.
- **`FunctionalAssessment`** — результат анкеты: возможности, уровень по тесту,
  GMFCS врача, итоговый (осторожный) уровень, исключённые риски, нужен ли допуск.
- **`Exercise` / `ExerciseVariant`** — упражнение: часть занятия, цели, положение,
  требуемые возможности, уровни, минимальный возраст, риски, 3 варианта сложности, видео.
- **`SessionLog` / `WorkoutPlan` / `PlannedExercise`** — занятие и его план, общий и
  поэлементный отзыв, боль и её признаки, длительность.
- **`ProgressMap` / `ExerciseProgress`** — сложность и «серия лёгких» по каждому упражнению.
- **`PracticeLog`** — отдельно сделанное упражнение вне занятия.
- **`FamilyGoal` / `GoalReview`** — цель семьи и её оценки (−2…+2).
- **`TrackingTest` / `TrackingResult`** — тесты динамики и их результаты.

### UI и общие модули

- `src/ui/kit.tsx` — дизайн-система (темы, компоненты). ⚠️ Цвет не привязывать к гендеру.
- `src/ui/ExerciseVideo.tsx` — видео упражнения (expo-video; полноэкранный режим).
- `src/ui/useStopwatch.ts` — секундомер для тестов динамики и занятий.
- `src/ui/ArticleBody.tsx` — рендер статей.
- `src/chat/`, `src/admin/`, `src/content/` — чат с куратором, админ-инструменты, статьи.

### Что с бэкендом

Сейчас всё хранится **локально** на устройстве. Следующий шаг (отмечен в коде и
README) — синхронизация с сервером, чтобы куратор видел прогресс, а данные не
терялись при смене телефона. Это согласуется с принципом продукта «пользоваться
не только в РФ» и сценарием проверки на 10 семьях (см.
[разделы/01-концепция-принципы-рынок.md](разделы/01-концепция-принципы-рынок.md)).

## Расхождения доски и кода

Продуктовые решения по этим расхождениям приняты и зафиксированы в
[разделы/07-решения.md](разделы/07-решения.md); клинические величины по-прежнему ждут
подписи специалиста.

1. **Модель навыков.** На доске — 5 навыков (сидение, вставание, стояние, ходьба,
   перемещение на пол); в коде — тест из 5 пунктов (голова/сидение, стояние, ходьба,
   лестница, бег). **Решено (Р1):** канонической остаётся модель из 5 пунктов; модель
   доски — идеи на будущее.
2. **Гранулярность подбора.** Доска предлагает развёрнутое дерево «навык → утверждение
   → упражнения»; код работает по функциональному уровню. **Решено (Р2):** дерево — вне
   MVP (этап «Потом»), требует упражнений от специалиста.
3. **UI-пожелания** из [разделы/06-ui-аннотации.md](разделы/06-ui-аннотации.md)
   в основном реализованы: видео на весь экран (`ExerciseVideo`), «мордочки»
   самочувствия (`FaceChoiceRow`), сложность иконками-точками (`DifficultyDots`),
   вопрос «Как ребёнок сегодня?» до занятия, нейтральный цвет темы, «Моя цель».
   Полную сверку с референсами доски стоит провести отдельным UX-ревью.
