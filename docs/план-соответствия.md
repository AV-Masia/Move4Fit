## Пошаговый план

Легенда оценки: **S** ≈ часы, **M** ≈ дни, **L** ≈ недели+.

### Этап 0 — проектное решение по модели подбора (блокирует Этап 4) · L · владелец: продукт + методист
Не выбирать вслепую «уровни 1–5 **или** доска». Рассмотреть **три** варианта, по
умолчанию — гибрид:
- **A. Оставить уровни 1–5** — минимум изменений, но теряем гранулярность доски.
- **B. Полностью перейти на дерево доски** — максимально по доске, но переписываем ядро и теряем готовую логику безопасности.
- **C. Гибрид (рекомендуется).** Уровень 1–5 остаётся как **слой безопасности/гейтинга**
  (`clearanceRequired`, осторожность по GMFCS, исключения по флагам уже есть), а дерево
  доски добавляется как **слой фильтрации упражнений** поверх — через существующие
  `Capability` и `Exercise.position`. Тогда Этап 4 — это расширение `selection.ts`, а
  не переписывание `functionalLevel.ts`.

**Результат этапа — письменный артефакт**, а не просто «выбрали вариант»:
1. Таблица маппинга `навык доски → Capability / Position → фильтр упражнений`.
2. Решение по гибриду (что остаётся слоем безопасности, что — слоем подбора).
3. Набор **golden-тестов безопасности** (профили: флаги × ответы → ожидаемые
   исключения и факт блокировки автоподбора). Эти тесты фиксируются **до** Этапа 4
   и должны проходить на обеих моделях.

*Критерий приёмки:* маппинг и golden-тесты закоммичены; методист подтвердил маппинг.

### Этап 1 — быстрые правки, низкий риск (раздел 06) · S
1. Убрать привязку темы к полу: `src/ui/kit.tsx:120 defaultThemeFor` + места вызова —
   тема по умолчанию нейтральная, выбирается родителем независимо от `sex`.
   - **Миграция:** добавить поле темы в профиль/настройки и экран выбора; для уже
     созданных профилей при чтении подставлять нейтральную тему по умолчанию
     (не падать на отсутствии поля).
2. Переименовать «Цель» → **«Моя цель»**, завести **«Мои успехи»**
   (`app/goal.tsx`, `app/(tabs)/progress.tsx`).
3. Сложность — иконками вместо «Сложность N из 3», сохранив `accessibilityLabel`
   (`app/exercise/[id].tsx`, `app/workout.tsx`).

*Критерий приёмки:* тема не зависит от пола ни на одном экране; старые профили
открываются без ошибок; скринридер по-прежнему читает сложность.

## Критический путь и порядок

Почти весь риск сосредоточен на пути **Этап 0 → 4a → 4b**. Быстрые победы (Этапы 1, 1.5)
и UX тренировки (Этап 2, после UX-ревью) и модель фидбэка (Этап 3) идут параллельно и
**не** блокируются решением по модели подбора. Этап 0 обязателен до Этапа 4 и заодно
страхует его golden-тестами безопасности.
